# Руководство администратора Immich на NICK-SERV

Историческая подробная справка Immich, актуализирована 08.11.2026. Основное руководство всей системы: [оглавление](../README.md). Это руководство для существующей установки, не сценарий повторной установки. Команды Linux выполнять по SSH на NICK-SERV под `nick`; команды PowerShell — на клиентском Windows-компьютере. Блоки изменения настроек выполнять по отдельности, проверяя результат. Сервер при подготовке руководства удалённо не менялся.

## 2. Способы входа

| Откуда | Адрес | Условия |
| --- | --- | --- |
| iPhone или компьютер | HTTPS URL из `sudo tailscale serve status` | Tailscale подключён к разрешённой сети; уже работает |
| Сам сервер | http://127.0.0.1:2283 | Для curl/диагностики; localhost относится именно к серверу |
| Компьютер через SSH-туннель | http://localhost:12283 | Резервный способ, пока окно SSH открыто |
| Устройство в домашней сети без Tailscale | http://LAN_IP:2283 | Привязка настроена; проверить с другого устройства |

Для администрирования в браузере войти обычным администраторским аккаунтом Immich, затем открыть меню профиля → «Администрирование». Отдельного административного порта нет. Пароли Immich, SSH и PostgreSQL — разные учётные данные.

### Резервный SSH-туннель

PowerShell, подставить фактический SSH-адрес только локально:

```powershell
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:12283:127.0.0.1:2283 nick@SERVER_ADDRESS
```

Открыть http://localhost:12283 на этом компьютере. Ctrl+C закрывает туннель, Immich продолжает работать. Дома SERVER_ADDRESS может быть LAN IPv4 сервера; извне нужен доступный SSH-маршрут (например, Tailscale). Сам туннель шифруется, хотя локальная ссылка имеет http.

### Tailscale

```bash
sudo tailscale serve status
systemctl is-active tailscaled
```

Использовать выданный HTTPS URL без добавления `:2283` или `/api`. Не публиковать персональное имя tailnet. Serve настроен через `--bg`; выход из SSH не отключает его. При сбое не выполнять `tailscale serve reset` вслепую — сначала прочитать конфигурацию. Подробности: [TAILSCALE.md](TAILSCALE.md).

## 3. Прямой доступ из домашней сети

LAN-привязка уже применена 02.11.2026: запрос с сервера вернул HTTP 200, localhost и Tailscale сохранены. Повторно добавлять порт не нужно. Ниже сохранена процедура для осознанного изменения адреса. Это даёт вход с телефона/компьютера в домашнем Wi-Fi без Tailscale. За пределами дома остаётся HTTPS Tailscale. Один и тот же аккаунт и медиатека доступны через оба адреса.

### Узнать LAN IPv4

На сервере:

```bash
ip -4 -brief address
ip -4 route show default
```

Нужен адрес физического интерфейса, связанного с домашним роутером. Не брать 127.0.0.1, tailscale0, docker0, br-* или WAN-адрес роутера. Не угадывать IP по старым скриншотам. Закрепить текущий LAN IP за сервером в DHCP роутера; пункты меню зависят от его модели. Если закреплённый адрес изменится, Docker не сможет привязаться к старому адресу и запуск Immich завершится ошибкой.

### Добавить LAN-порт, сохранив Tailscale

Только после определения и закрепления адреса. Понадобится краткая остановка Immich; другие сервисы не перезапускаются. Сначала создать локальную копию Compose:

```bash
cd /home/nick/immich-app
cp -p docker-compose.yml "docker-compose.yml.before-lan-$(date +%Y%m%d-%H%M%S)"
nano docker-compose.yml
```

В `services: immich-server: ports:` оставить существующую строку и добавить вторую. `LAN_IP` обязательно заменить реальным IPv4, это не готовое значение:

```yaml
    ports:
      - '127.0.0.1:2283:2283'
      - 'LAN_IP:2283:2283'
```

Не менять restart policies и пути данных. Не заменять адрес на `0.0.0.0` или просто `2283:2283`: это расширяет публикацию на другие интерфейсы. PostgreSQL и Valkey наружу не публиковать.

```bash
sudo docker compose config --quiet
```

При ошибке исправить файл до перезапуска. Если проверка прошла:

```bash
sudo /usr/local/sbin/immich-check-storage
sudo systemctl restart immich
sudo docker compose ps -a
curl -I --max-time 10 http://127.0.0.1:2283
```

Дождаться healthy; на другом устройстве в той же доверенной домашней сети открыть `http://LAN_IP:2283`. При проверке прямого LAN-доступа временно выключить Tailscale на клиенте. Затем включить его и убедиться, что прежний HTTPS URL также работает.

HTTP по LAN не шифрует пароль и фото между устройством и сервером. Использовать только в доверенной домашней сети; для HTTPS уже есть Tailscale. Гостевой Wi-Fi может изолировать устройства. Привязка к LAN IP ограничивает адрес назначения, но не заменяет правила сетевого доступа, если между сетями настроена маршрутизация. Docker может обходить обычные правила UFW. Проброс портов на роутере и DMZ для этого не нужны.

### Отмена изменения LAN

Из списка `ls -lt docker-compose.yml.before-lan-*` выбрать точную копию, созданную перед этим изменением. Открыть её и сравнить с текущим файлом перед восстановлением. Не использовать wildcard в команде копирования:

```bash
cp -p docker-compose.yml.before-lan-YYYYMMDD-HHMMSS docker-compose.yml
sudo docker compose config --quiet
sudo systemctl reset-failed immich
sudo systemctl restart immich
```

Заменить имя копии на существующее. Проверить localhost и Tailscale; LAN-порт исчезнет.

## 4. Где находятся данные

| Путь на сервере | Назначение |
| --- | --- |
| /home/nick/immich-app/docker-compose.yml | Описание четырёх контейнеров |
| /home/nick/immich-app/.env | Пути, версия, пароль PostgreSQL; права 600 |
| /home/nick/immich-app/postgres | Рабочие файлы PostgreSQL на NVMe |
| /mnt/photos/immich | Весь UPLOAD_LOCATION на HDD; внутри контейнера /data |
| /mnt/photos/immich/backups | Место встроенных дампов БД, если они созданы; наличие проверить |
| Docker volume model-cache | Модели ML; точное размещение смотреть через Docker |
| /etc/systemd/system/immich.service | Управление стеком |
| /usr/local/sbin/immich-check-storage | Проверка HDD перед стартом |
| /etc/fstab | Монтирование HDD по UUID |

В медиатеке могут быть `upload`, `library`, `thumbs`, `encoded-video`, `profile`, `backups`; не перемещать их вручную. Наличие папки `library/admin/год/месяц/день` зависит от шаблона хранилища, сохранение которого пока не подтверждено. Не считать видимую папку `library` единственным местом оригиналов.

Текущая запись fstab:

```fstab
UUID=f8d17a00-1f7e-4ed9-86be-2a71af0587b7 /mnt/photos ext4 defaults,nofail,x-systemd.device-timeout=15s 0 2
```

`nofail` позволяет загрузить ОС без диска. Скрипт запуска проверяет отдельный mount, UUID, ext4, rw и отсутствие symlink у каталога медиатеки. Не запускать контейнеры вручную в обход него.

## 5. Запуск и остановка

Выполнять только нужную команду, не весь блок подряд:

```bash
sudo systemctl status immich --no-pager -l
sudo systemctl stop immich
sudo systemctl start immich
sudo systemctl restart immich
```

Сервис работает с Compose на переднем плане. Выход одного контейнера останавливает стек и вызывает повторный запуск через systemd. После трёх быстрых неудачных попыток за 300 секунд срабатывает ограничение. Устранить причину, затем:

```bash
sudo systemctl reset-failed immich
sudo systemctl start immich
```

После изменения самого unit:

```bash
sudo systemctl daemon-reload
sudo systemd-analyze --generators verify /etc/systemd/system/immich.service
```

После успешной проверки перезапустить Immich. Изменение только Compose или .env не требует daemon-reload, но требует перезапуска для применения. `docker compose up -d` здесь не использовать. Перезапуск всего Docker затрагивает другие контейнеры и может оставить Immich остановленным из-за BindsTo; после него явно проверить сервис.

## 6. Проверка состояния

```bash
sudo /usr/local/sbin/immich-check-storage
systemctl is-active immich docker tailscaled
systemctl is-enabled immich docker tailscaled
cd /home/nick/immich-app
sudo docker compose ps -a
curl -I --max-time 10 http://127.0.0.1:2283
df -hT / /mnt/photos
df -i / /mnt/photos
sudo docker stats --no-stream
sudo tailscale serve status
```

Ожидаются успешная проверка HDD, active/enabled, четыре healthy, HTTP 200. Результат сразу после старта может быть переходным; проверить ещё раз после инициализации. `systemctl status` показывает память процесса Compose, не всех контейнеров. Для памяти контейнеров использовать docker stats.

Просмотр логов:

```bash
sudo journalctl -u immich -b --no-pager -n 100
cd /home/nick/immich-app
sudo docker compose logs --tail=100 immich-server database
```

Логи могут содержать имена файлов, пользователей и адреса: перед публикацией обезличить. Не отправлять `.env`, `docker inspect` целиком или полный `docker compose config` — там могут быть пароли.

## 7. Перезагрузка

Проверка после перезагрузки пока не выполнена. Перезагрузка прервёт ботов, Tailscale и Immich; выбрать момент без загрузки фото и иметь возможность добраться до локальной консоли.

```bash
sudo findmnt --verify --verbose
sudo /usr/local/sbin/immich-check-storage
sudo systemctl is-enabled immich docker tailscaled
```

При отсутствии ошибок и в выбранное время:

```bash
sudo reboot
```

После повторного подключения выполнить раздел 6 и:

```bash
systemctl --failed --no-pager
systemctl is-active nutrition-bot adguardvpn-bot tailscaled tailscale-relay
```

Проверить вход с iPhone и наличие тестовых фотографий. Если SSH не вернулся, использовать локальную консоль и диагностировать boot/fstab; не форматировать диск. Подробности: [OPERATIONS.md](OPERATIONS.md).

## 8. Пользователи и фотографии

Через меню «Администрирование» управлять пользователями, квотами, заданиями и настройками. Членам семьи создавать отдельные аккаунты; не передавать пароль администратора. Шаблон хранилища управляет размещением на диске, альбомы — организацией внутри приложения. Не переименовывать файлы оригиналов вручную.

Если забыт пароль администратора, команда выполняется интерактивно на сервере:

```bash
cd /home/nick/immich-app
sudo docker compose exec immich-server immich-admin reset-admin-password
```

Следовать подсказкам, новый пароль сохранить приватно; при подозрении на чужой доступ завершить существующие сессии. Это не смена DB_PASSWORD. Правка DB_PASSWORD в .env не меняет пароль уже созданного пользователя PostgreSQL.

### Если iPhone не видит фото

1. В iOS открыть Настройки → Приложения → Immich → Фото (либо Конфиденциальность и безопасность → Фото → Immich) и проверить доступ. Для всей медиатеки нужен полный доступ; при ограниченном видны только разрешённые снимки.
2. Вернуться в Immich, открыть раздел загрузки/облако и список альбомов устройства. Пустая серверная лента сама по себе не доказывает, что локальные фото недоступны.
3. Создать в «Фото» тестовый альбом из 2–3 снимков и выбрать только его. Убедиться, что Tailscale подключён; для первого теста использовать Wi-Fi и держать Immich открытым.
4. Если альбомы по-прежнему отсутствуют, зафиксировать версии iOS/приложения и экран разрешений; не переустанавливать приложение и не сбрасывать настройки сервера вслепую.

Полный доступ к Фото не равнозначен выбору всех альбомов для отправки. «Backup» в мобильном приложении означает загрузку с телефона на сервер; отдельная резервная копия самого сервера — другая задача. На iOS фоновая отправка зависит от ограничений ОС; её работа не гарантируется сразу после каждого снимка. Оригиналы из iCloud могут предварительно скачиваться на телефон.

Тест: загрузить фото, увидеть его в веб-интерфейсе, скачать оригинал. Для сравнения файлов в PowerShell:

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath 'C:\path\original.jpg'
Get-FileHash -Algorithm SHA256 -LiteralPath 'C:\path\downloaded.jpg'
```

Пути заменить своими. Сравнивать исходный файл и скачанный оригинал, не миниатюру и не экспорт с преобразованием формата. Не удалять исходники и не запускать «Освободить место» до понимания последствий, особенно при синхронизации iCloud.

## 9. Обновление

Текущая зафиксированная версия — v3.3.5. Автоматические обновления контейнеров не настроены. Этот раздел — процедура на будущее, обновление сейчас не выполняется.

1. Прочитать release notes целевого релиза и переходов между версиями, проверить совместимость клиента. Не выбирать тег release/latest вместо точной версии.
2. Иметь восстановимую копию данных и базы. Внешнее копирование отложено: до его появления не выполнять плановую миграцию ценных данных без отдельного согласованного плана восстановления.
3. Сохранить конфигурацию приватно на сервере (это не независимая резервная копия):

```bash
cd /home/nick/immich-app
umask 077
snapshot_dir="config-before-upgrade-$(date +%Y%m%d-%H%M%S)"
mkdir -m 700 "$snapshot_dir"
cp -p .env docker-compose.yml "$snapshot_dir/"
sudo systemctl cat immich > "$snapshot_dir/immich.service.txt"
cp /usr/local/sbin/immich-check-storage "$snapshot_dir/immich-check-storage"
```

4. Скачать Compose и example.env **целевого релиза** под новыми именами и сравнить с текущими. Не перезаписывать рабочую .env шаблоном. Сохранить свои пути, DB_PASSWORD, localhost/LAN-привязки, четыре restart: "no" и совместимость с systemd. Изменения PostgreSQL выполнять только по инструкции релиза.
5. В .env указать выбранный IMMICH_VERSION и применить необходимые изменения Compose. Затем:

```bash
sudo docker compose config --quiet
sudo docker compose pull
```

Если скачивание/валидация не удались, не перезапускать работающий стек: исправить или вернуть конфигурацию, чтобы случайный restart не применил незавершённое обновление.

6. После успешной подготовки:

```bash
sudo systemctl restart immich
sudo docker compose ps -a
sudo journalctl -u immich --no-pager -n 100
curl -I --max-time 10 http://127.0.0.1:2283
```

7. Проверить вход, тестовый оригинал, загрузку и Tailscale. Записать версию и результат в журнал.

Downgrade Immich не поддерживается: после миграции базы нельзя просто вернуть старый тег. При сбое остановить стек, сохранить состояние и использовать согласованную предобновлённую копию с подходящей версией в отдельном восстановительном окружении. Старые образы не удалять до завершения проверки.

## 10. Диагностика

| Симптом | Что проверить |
| --- | --- |
| Не открывается ни localhost, ни HTTPS | immich status, compose ps, journal; не начинать с перенастройки Tailscale |
| Localhost работает, HTTPS нет | Serve status, tailscaled, подключение клиента и правила tailnet |
| HTTPS работает, LAN нет | Неверный LAN IP или привязка, гостевой Wi-Fi, клиентская изоляция |
| Start request repeated too quickly | Устранить первую ошибку в журнале, затем reset-failed и start |
| Storage check failed | mount/UUID/rw/каталог; никаких mkfs или создания пустой библиотеки |
| Один контейнер падает, остальные останавливаются | Так работает abort-on-container-exit; искать первичную ошибку конкретного контейнера |
| Все running, но не healthy | Посмотреть логи конкретного сервиса; health не равен наличию процесса |
| Закончился NVMe | df -h, df -i, docker system df; не удалять postgres и volumes |
| Фото не появляются на сервере | Разрешения Фото, выбранный альбом, очередь отправки, сеть, свободное место |

Для диска:

```bash
findmnt --mountpoint /mnt/photos -o SOURCE,UUID,FSTYPE,OPTIONS,TARGET
lsblk -o NAME,SIZE,MODEL,FSTYPE,LABEL,UUID,MOUNTPOINTS
sudo journalctl -b -u mnt-photos.mount --no-pager -n 80
sudo journalctl -k -b --no-pager -n 100
```

Если HDD отсутствует, оставить Immich остановленным. После устранения причины проверить mount скриптом, затем start. При замене HDD UUID изменится: обновить fstab и скрипт проверки осознанно, после восстановления данных. Не подставлять новый UUID только ради запуска пустой медиатеки.

SMART проверять после сопоставления текущего имени устройства с моделью HDD: `sudo smartctl -H -A /dev/sda`. Показанные ранее PASSED и 28 °C не гарантируют исправность сегодня. При росте pending/reallocated/uncorrectable сначала обеспечить сохранность данных. Инструкция тестов — [OPERATIONS.md](OPERATIONS.md).

## 11. Резервные копии и восстановление

По решению владельца отдельное копирование **отложено до покупки внешнего HDD**. Расписание, новый сервис копирования и внешняя копия не создавались. Встроенные настройки дампов БД не изменялись, наличие свежих дампов ещё не проверено.

Будущий комплект восстановления: весь UPLOAD_LOCATION, согласованный дамп базы, конфигурация с секретами в защищённом виде, точные версии и, при наличии, внешние библиотеки. Дамп базы не содержит фото; папка базы на NVMe не является резервной копией. Второй раздел того же диска не защищает от отказа носителя.

Порядок при потере сервера/диска:

1. Остановить запись и сохранить оставшиеся данные; не форматировать повреждённый носитель.
2. Подготовить отдельное окружение с совместимыми версиями, восстановить медиатеку с правильными путями и правами.
3. Восстановить дамп средствами соответствующего релиза. В актуальной документации предусмотрен интерфейс Administration → Maintenance; операция заменяет текущую базу, поэтому выполнять её только с выбранной копией и пониманием последствий.
4. Проверить аккаунты, альбомы, несколько фото и видео, скачивание оригиналов. Только после проверки возвращать запись и автозагрузку.

Не копировать работающий postgres как единственную копию и не пытаться восстановить аккаунты/альбомы одним помещением фотографий в library. Точные команды для внешнего диска и расписание добавить после его покупки, выбора точки монтирования и проверки восстановления.

## 12. Правила эксплуатации и источники

- Не выполнять mkfs/parted/wipefs для исправления проблем доступа. Они могут уничтожить данные.
- Не применять `docker compose down -v`, `docker system prune --volumes` и рекурсивный chown к PostgreSQL как обычную диагностику.
- Не публиковать `.env`, дампы, адреса сети, токены, фотографии и диагностические выводы с персональными данными.
- Не отключать UFW/защиту mount ради устранения ошибки. Docker-порты требуют отдельного понимания фильтрации.
- Не включать Funnel и проброс портов на роутере для текущей приватной схемы.

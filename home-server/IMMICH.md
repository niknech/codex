# Immich: следующий этап, ещё не выполнен

Все действия этого документа — план. Сейчас Immich, PostgreSQL, аккаунт администратора и резервное копирование **не настроены**.

## 1. Проверить ресурсы и выбрать релиз

```bash
lscpu
free -h
df -hT / /mnt/photos
docker compose version
```

Сверить результат с [требованиями выбранной версии](https://docs.immich.app/install/requirements/). На дату подготовки текущая документация указывает минимум 6 GB RAM и 2 ядра, рекомендует 8 GB и 4 ядра; для ML в v3 на amd64 требуется x86-64-v2. Фактические CPU/RAM сервера ещё не зафиксированы. Базу разместить на локальном NVMe, предусмотреть место для Docker, моделей и роста базы; медиатеку — на HDD.

## 2. Получить конфигурацию одного конкретного релиза

Использовать [официальный Compose](https://docs.immich.app/install/docker-compose/) и [релизы](https://github.com/immich-app/immich/releases). Ниже версия вводится вручную, чтобы Compose, example.env и образы относились к одному выбранному релизу; `latest` не фиксирует версию.

Команды выполняются пользователем `nick`. Каталог должен быть новым: не перезаписывать существующую конфигурацию.

```bash
mkdir -m 700 ~/immich-app
cd ~/immich-app
read -r -p 'Точный тег выбранного релиза (vX.Y.Z): ' IMMICH_RELEASE
test -n "$IMMICH_RELEASE" || exit 1
umask 077
curl -fL "https://github.com/immich-app/immich/releases/download/${IMMICH_RELEASE}/docker-compose.yml" -o docker-compose.yml
curl -fL "https://github.com/immich-app/immich/releases/download/${IMMICH_RELEASE}/example.env" -o .env
nano .env
chmod 600 .env
```

При ошибке скачивания остановиться. В `.env` задать:

```dotenv
UPLOAD_LOCATION=/mnt/photos/immich
DB_DATA_LOCATION=/home/nick/immich-app/postgres
TZ=Europe/Moscow
# Вместо следующей заглушки — тот же точный тег релиза:
IMMICH_VERSION=vX.Y.Z
# Вместо заглушки — новый случайный пароль только в локальном .env:
DB_PASSWORD=REPLACE_WITH_RANDOM_SECRET
```

Сохранить остальные переменные из example.env выбранного релиза. Пароль можно получить локально командой `openssl rand -hex 32`; не копировать его в GitHub или чат. Не запускать с заглушками. Не менять пароль уже инициализированной базы простым редактированием `.env`.

## 3. До запуска: mount и доступ

```bash
mountpoint -q /mnt/photos || exit 1
test "$(findmnt -n -o UUID --mountpoint /mnt/photos)" = \
  'f8d17a00-1f7e-4ed9-86be-2a71af0587b7' || exit 1
test -d /mnt/photos/immich || exit 1
test -w /mnt/photos/immich || exit 1
```

Эта ручная проверка защищает только текущий запуск. **До включения постоянного автозапуска** настроить зависимость от `/mnt/photos` и проверку UUID. Варианты: отдельный systemd-сервис для стека с `RequiresMountsFor=/mnt/photos` и проверкой UUID перед стартом либо зависимость Docker от mount (затронет все контейнеры). Учесть `restart: always` / `unless-stopped` в Compose: Docker способен запустить такие контейнеры раньше отдельного сервиса. Не считать один `ExecStartPre` достаточным, пока этот обход не устранён. Проверить поведение при недоступном HDD до загрузки реальных фотографий.

В `docker-compose.yml` заменить публикацию порта сервиса Immich на loopback, сохранив внутренний порт из файла релиза (для конфигурации с 2283):

```yaml
ports:
  - '127.0.0.1:2283:2283'
```

Не добавлять это второй строкой к существующей публикации на всех интерфейсах. Не публиковать PostgreSQL/Redis наружу. См. [риски Docker/UFW](SETUP.md#docker-и-ufw).

## 4. Первый пробный запуск

После выполнения предыдущих условий:

```bash
cd ~/immich-app
sudo docker compose config --quiet
sudo docker compose pull
sudo docker compose up -d
sudo docker compose ps
sudo docker compose logs --tail=100
curl -I http://127.0.0.1:2283
```

Не публиковать полный вывод `docker compose config`: он может содержать подставленный пароль. Проверять ошибки в логах и состояние контейнеров, а не только факт запуска.

На клиентском компьютере, подставив адрес сервера только локально:

```bash
ssh -L 2283:127.0.0.1:2283 nick@SERVER_ADDRESS
```

Открыть `http://localhost:2283`, создать администратора и проверить загрузку/скачивание нескольких тестовых фотографий. Такой туннель предназначен для начальной настройки; мобильная автозагрузка требует отдельно настроенного доступа. VPN или HTTPS reverse proxy, домен и доступ извне пока не выбраны.

## 5. Отдельная резервная копия обязательна

Один HDD, SMART PASSED и загрузка фотографий в Immich не заменяют резервную копию. Копия на том же HDD не защищает от его отказа. Дамп PostgreSQL **не содержит фотографии**; одни фотографии не восстанавливают аккаунты, альбомы и метаданные базы. См. [официальное руководство backup/restore](https://docs.immich.app/administration/backup-and-restore/).

До массового импорта выбрать отдельный диск/NAS/облачное хранилище, шифрование и расписание. Сохранять:

- Весь `UPLOAD_LOCATION`, включая оригиналы, видео и каталог резервных дампов.
- Согласованный дамп базы средствами выбранной версии Immich.
- Compose, точную версию приложения и конфигурацию; `.env` — только в защищённой резервной копии, вне Git.
- Внешние библиотеки отдельно, если будут подключены.

Для первой копии остановить загрузки и изменения, создать свежий дамп базы по инструкции установленного релиза, остановить стек и скопировать медиатеку, дамп и конфигурацию на независимый носитель. Не считать копирование работающего каталога PostgreSQL согласованной резервной копией. Затем запустить стек и проверить результат задания копирования. Настроить сроки хранения и уведомления об ошибках; стремиться к схеме 3-2-1 с копией вне дома.

### Проверка восстановления

1. Подготовить отдельное тестовое окружение и релиз, совместимый с дампом; сохранить текущие данные перед любым восстановлением.
2. Восстановить медиатеку и конфигурацию с исходными путями; проверить права и mount.
3. Восстановить базу по инструкции **именно установленного релиза**: команды и процедура менялись между версиями. Не подставлять старые SQL-команды вслепую.
4. Проверить вход, альбомы, количество объектов и скачивание нескольких оригиналов/видео.
5. Записать дату, версию, местоположение копии и результат проверки без секретов.

Автоматическое копирование и восстановление пока не проверены; после выбора носителя и релиза дополнить этот документ точными командами для них.

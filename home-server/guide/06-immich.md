# 6. Фотографии в Immich

[Оглавление](../../README.md) · [Назад](05-wifi.md) · [Далее](07-backups.md)

## Открыть фотографии

| Откуда | Как открыть |
|---|---|
| Обычная домашняя LAN | `http://192.168.1.91:2283` |
| Извне | Включить Tailscale; использовать HTTPS-адрес из `sudo tailscale serve status` |
| Сам сервер, диагностика | `http://127.0.0.1:2283` |

LAN-привязка уже настроена, запрос с самого сервера вернул HTTP 200. Проверка с другого LAN-устройства ещё не зафиксирована. При смене домашнего IP нужно согласованно исправить привязку Compose; лучше закрепить IP на роутере. HTTPS через Tailscale проверен с iPhone. Адрес HTTPS вводится без `:2283` и `/api`. Личный адрес tailnet не публикуем.

В домашнем HTTP трафик не шифруется: используй доверенную сеть либо HTTPS через Tailscale. Wi-Fi NICK-VPN изолирован от самого сервера; это не тот же доступ, что обычная LAN.

Резервный способ — SSH-туннель. **НОУТБУК:**

```powershell
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:12283:127.0.0.1:2283 nick@192.168.1.91
```

Пока окно открыто, в браузере ноутбука доступен `http://localhost:12283`. Вне дома замени SSH-адрес на Tailscale. Ctrl+C закроет туннель, не сервер.

## Пользователи и загрузка

В веб-интерфейсе войди администратором, открой меню профиля → **Администрирование**. В разделе пользователей можно создать отдельную учётную запись члену семьи. Не раздавай свой пароль администратора. Удаление пользователя может затронуть его фотографии: сначала проверь предупреждение интерфейса и копии.

На iPhone:

1. Включи Tailscale и проверь HTTPS в Safari.
2. В Immich введи тот же адрес и свои учётные данные.
3. В настройках iOS разреши Immich доступ к нужным фото; для всей медиатеки нужен полный доступ.
4. В разделе загрузки Immich выбери альбомы. Для первого теста — отдельный альбом с 2–3 снимками.
5. Держи приложение открытым до завершения. Убедись в веб-интерфейсе, что фото появилось; скачай оригинал и проверь его.

После успешной проверки включай загрузку нужных альбомов. Фоновую отправку на iOS ограничивает система; мгновенная загрузка каждого снимка не гарантируется. Лента сервера и локальные альбомы телефона — разные экраны.

«Освободить место» используй только после проверки загрузки и независимой копии. При включённых «Фото iCloud» удаление с телефона затронет iCloud и синхронизированные устройства. Загрузка в Immich сама по себе не создаёт копию на другом диске сервера.

## Служба и данные

| Что | Где |
|---|---|
| Управление всем стеком | `immich.service` |
| Compose и `.env` | `/home/nick/immich-app` |
| PostgreSQL | `/home/nick/immich-app/postgres` на NVMe |
| Вся медиатека | `/mnt/photos/immich` на HDD |
| Проверка диска | `/usr/local/sbin/immich-check-storage` |

Фотографии могут быть и в `upload`, и в `library`. Не переноси папки вручную; сохраняй весь каталог медиатеки. `.env` содержит секреты, не публикуй её.

**СЕРВЕР — проверка:**

```bash
sudo /usr/local/sbin/immich-check-storage
systemctl status immich --no-pager
cd /home/nick/immich-app
sudo docker compose ps -a
curl -I --max-time 10 http://127.0.0.1:2283
```

Проверка диска должна завершиться успешно; после запуска ожидаем четыре healthy и HTTP 200. `health: starting` сразу после старта возможно; если сохраняется, изучи журнал. Сервер, ML, PostgreSQL и Valkey выполняют разные задачи. ML обрабатывает поиск и лица, не хранит оригиналы вместо HDD.

Выбери нужное действие:

| Действие | Команда |
|---|---|
| Остановить | `sudo systemctl stop immich` |
| Запустить | `sudo systemctl start immich` |
| Перезапустить | `sudo systemctl restart immich` |
| Журнал | `sudo journalctl -u immich -n 100 --no-pager` |

Используем существующую службу с проверкой HDD. **Не запускай `docker compose up -d` в обход неё.** В этой настройке падение контейнера останавливает стек и вызывает повторный запуск. При лимите запусков сначала исправь причину, затем `sudo systemctl reset-failed immich` и `sudo systemctl start immich`.

## Если сервер шумит при импорте

Сначала проверь температуры и `sudo docker stats --no-stream`. При нормальных температурах временно ограничить CPU без перезапуска:

```bash
sudo docker update --cpus 1 immich_machine_learning
sudo docker update --cpus 2 immich_server
```

Обработка станет медленнее. Через несколько минут повтори измерения. Отмена — те же команды с `--cpus 0`. Лимиты не переживают пересоздание контейнеров. Для постоянных лимитов после резервирования добавь в существующие сервисы Compose `cpus: 1.0` у `immich-machine-learning` и `cpus: 2.0` у `immich-server`, сохранив отступы. Проверь `sudo docker compose config --quiet`, затем перезапусти службу в удобное время. Выполнение временных лимитов в прошлой переписке не подтверждено.

## Обновить Immich

Последняя подтверждённая версия — **v3.3.5**, это исторический факт, не рекомендация «самой новой» версии.

1. Создай и проверь независимую копию по разделу 7. Прочитай [заметки целевого выпуска](https://github.com/immich-app/immich/releases) и [порядок обновления](https://docs.immich.app/install/upgrading/).
2. Сохрани `.env`, Compose и unit приватно. Выбери точную версию, не плавающий latest.
3. Сравни Compose выбранного выпуска с текущим. Сохрани пути, пароль БД, localhost/LAN-привязки и четыре `restart: "no"`, необходимые этой службе. Не подменяй `.env` шаблоном.
4. В `/home/nick/immich-app` выполни:

```bash
sudo docker compose config --quiet
sudo docker compose pull
```

5. Только если обе команды успешны: `sudo systemctl restart immich`.
6. Проверь четыре контейнера, вход, старые фото, скачивание оригинала и новую загрузку.

Если подготовка не удалась, верни прежнюю конфигурацию до любого рестарта. После миграции БД простой возврат старого тега не является откатом: downgrade не поддерживается. Нужен согласованный комплект данных до обновления и подходящая версия. Не удаляй прежние образы до проверки.

Подробности первоначальной установки: [SETUP](../SETUP.md), [CONFIGURE](../CONFIGURE.md), [SERVICE](../SERVICE.md). Это не команды ежедневного обслуживания.

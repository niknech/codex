# 3. Telegram-бот питания

## Где программа и данные

| Назначение | Путь / имя |
|---|---|
| Служба | `nutrition-bot.service` |
| Выбранный релиз | `/opt/nutrition-bot/current` — ссылка на папку релиза |
| База | `/var/lib/nutrition-bot/bot.sqlite3` |
| Настройки | `/etc/nutrition-bot/config.env` |
| Токен Telegram | `/etc/nutrition-bot/telegram_token` |
| Ключ AI | `/etc/nutrition-bot/ai_api_key` |
| Копии | `/var/backups/nutrition-bot` |
| Прокси | AdGuard `127.0.0.1:1080` |

Узнать выбранный релиз — **СЕРВЕР**:

```bash
readlink -f /opt/nutrition-bot/current
systemctl status nutrition-bot --no-pager
```

Последняя сборка из переписки не равнозначна подтверждённой установке: переключение через sudo требовало отдельного действия владельца. Не определяй версию только по ветке GitHub.

## Проверка и перезапуск

```bash
systemctl is-active nutrition-bot adguardvpn-bot
sudo journalctl -u nutrition-bot -n 60 --no-pager
```

Ожидаем два `active`. Если прокси работает, а бот завис:

```bash
sudo systemctl restart nutrition-bot
systemctl is-active nutrition-bot
```

В Telegram проверь `/start`, дневник и отдельный AI-запрос. Тестовые записи удали через меню. При ошибке 409 проверь, нет ли второго экземпляра с этим же токеном на ноутбуке.

## Добавить или убрать пользователя

1. Новый пользователь отправляет боту `/id` и передаёт числовой ID. Имя `@username` не подходит.
2. Сохрани настройки и открой редактор на сервере:

```bash
sudo cp -p /etc/nutrition-bot/config.env "/etc/nutrition-bot/config.env.before-users-$(date +%Y%m%d-%H%M%S)"
sudo nano /etc/nutrition-bot/config.env
```

3. В `BOT_ALLOWED_USER_IDS=` добавь ID через запятую, сохранив остальные. В версиях с публичной регистрацией для закрытого бота нужно `BOT_PUBLIC_REGISTRATION=false`. При `true` удаление ID из списка не закрывает доступ.
4. Ctrl+O → Enter → Ctrl+X, затем:

```bash
sudo systemctl restart nutrition-bot
systemctl is-active nutrition-bot
```

5. Новый пользователь отправляет `/start`. При ошибке проверь журнал; верни сохранённый config, если ошибка появилась после правки. Для удаления доступа убери нужный ID, не свой; история в базе останется.

Вариант с автоматическими проверками и откатом: [памятка версии с AI](https://github.com/niknech/codex/blob/3e85405/nutrition-bot/docs/BOT_COMMANDS.md).

## AI и лимиты

В `config.env`: `AI_ENABLED=false` отключает AI. Включение требует корректного ключа и доступной модели. `AI_DAILY_USER_LIMIT` и `AI_DAILY_GLOBAL_LIMIT` в версии с AI ограничивают попытки, а не точную стоимость в деньгах. Не заменяй весь файл примером.

Ключ редактируется отдельно:

```bash
sudo nano /etc/nutrition-bot/ai_api_key
```

Вставь ключ одной строкой, сохрани, затем:

```bash
sudo chmod 600 /etc/nutrition-bot/ai_api_key
sudo systemctl restart nutrition-bot
```

В версии с бонусами администратор в Telegram может отправить `/ai_bonus ID 5`, подставив числовой ID. Бонус действует до конца дня UTC (03:00 Москвы); общий лимит сохраняется. Право задаёт `BOT_ADMIN_USER_IDS`. Если команда неизвестна, проверь релиз.

## Выгрузить и вернуть базу

Для просмотра используй [согласованный снимок](07-backups.md); остановка не нужна. Прямое скачивание работающего `bot.sqlite3` может пропустить записи из WAL.

Для ручного редактирования сначала останови бота **до выгрузки свежей копии**:

```bash
sudo systemctl stop nutrition-bot
```

Выгрузи снимок, исправь его в DB Browser, нажми «Записать изменения», закрой базу. До возврата не запускай и не обновляй бота. Передача, проверка схемы, резервирование и возврат подробно описаны в [разделе 3.1 памятки](https://github.com/niknech/codex/blob/3e85405/nutrition-bot/docs/BOT_COMMANDS.md#31-загрузить-отредактированную-базу-обратно).

Возврат — **полная замена, не объединение**. Если после выгрузки кто-то пользовался ботом, старая копия затрёт новые записи, настройки и очереди. Для одной даты лучше исправить одну запись. После возврата проверь дневник и итоги: целостность SQLite не доказывает правильность ручных правок.

## Обновление и откат

1. Запиши текущий релиз через `readlink`.
2. Выбери конкретный проверенный коммит/тег. Не устанавливай `main` автоматически: новые функции имеют отдельную ветку.
3. Собери новый релиз в новой папке и выполни CTest по [инструкции установки](../../nutrition-bot/docs/SERVER.md).
4. Перед переключением останови бота, сохрани базу и настройки. Миграции сначала проверь на копии.
5. Переключи `current` по той же инструкции, запусти службу, проверь журнал, старые записи, ввод и AI.
6. Старую папку и копии сохрани до завершения проверки.

При несовместимой схеме откат требует и прежнего бинарника, и согласованной базы. Записи после копии потеряются. Старые `update-ai-*.sh` — установщики конкретных прошлых версий; не запускай их просто по знакомому имени.

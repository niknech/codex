# Дневник питания — Telegram-бот на C++20

Домашний многопользовательский бот: вода, вес, еда с подтверждением, личные нормы,
отчёты, PNG-графики и напоминания. Интерфейс на русском. SQLite хранит данные
и незавершённые операции. Входящие порты и домен не нужны: используется long polling.

**Все инструкции: [оглавление документации](docs/README.md).**
Для текущей установки: [инструкция администратора](docs/ADMIN_GUIDE.md) и
[полезные команды одним файлом](docs/BOT_COMMANDS.md).
Для уже настроенного Windows-ноутбука: [собрать и перезапустить одной командой](docs/WINDOWS.md).
Установка службы, обновление и восстановление: [SERVER.md](docs/SERVER.md).
Объяснение устройства для человека, знающего C: [CODE_TOUR.md](docs/CODE_TOUR.md).

## Что реализовано

- Личные чаты, доступ по Telegram ID, независимые данные пользователей.
- Вода `250`, `250 мл`, `0,5 л`; отмена конкретной записи.
- Вес в кг, выбор даты, подтверждение замены, одно измерение на день.
- Пошаговый ввод еды кнопками и опциональная AI-оценка описания.
- [Настройки, напоминания, нормы и отмена кнопками](docs/BUTTONS.md); команды также работают.
- Еда попадает в суммы только после подтверждения. Уточнение порции и правка БЖУ.
- История норм: первая норма с сегодня, изменения по умолчанию с завтра.
- IANA-часовые пояса, периоды 1–366 дней, страницы по 7 дней, график веса.
- Настраиваемые напоминания воды/калорий, выключены до явного включения.
- Персистентные inbox, outbox, AI jobs и состояния диалогов; миграция схемы.
- Секреты из файлов или systemd credentials; никаких токенов в исходниках.
- Автотесты без реальных Telegram/AI-запросов, Linux CI и сборка с санитайзерами.

## Быстрая сборка (Debian / Ubuntu / WSL Debian)

```bash
sudo apt update
sudo apt install build-essential cmake ninja-build git pkg-config \
  libcurl4-openssl-dev nlohmann-json3-dev libsqlite3-dev sqlite3 \
  libhowardhinnant-date-dev tzdata gnuplot-nox fonts-dejavu-core ca-certificates
cd nutrition-bot  # если вы стоите в корне репозитория codex
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build -j2
ctest --test-dir build --output-on-failure
```

## Локальный запуск

Создайте отдельного тестового бота у [BotFather](https://t.me/BotFather).
Сохраните токен в `.secrets/telegram_token` редактором, не командой с токеном.

```bash
mkdir -p .secrets data
chmod 700 .secrets data
nano .secrets/telegram_token
chmod 600 .secrets/telegram_token
export BOT_TOKEN_FILE="$PWD/.secrets/telegram_token"
export BOT_DB_PATH="$PWD/data/bot.sqlite3"
export BOT_ALLOWED_USER_IDS=123456789  # замените своим ID
export BOT_DEFAULT_TIMEZONE=Europe/Moscow
export AI_ENABLED=false
build/nutrition-bot --check-config
build/nutrition-bot --migrate
build/nutrition-bot --self-test
build/nutrition-bot --run
```

Если ID неизвестен, временно оставьте условный ID в allowlist, запустите бота и
отправьте `/id`: эта команда разрешена любому в личном чате и сообщает только
его собственный ID. Остановите Ctrl+C, задайте настоящий ID и запустите снова.
`--self-test` проверяет getMe, SELECT 1 и PNG; не отправляет сообщения и не вызывает AI.

В Telegram отправьте `/start`, затем `/help`. Меню содержит основные действия;
расширенные настройки и ввод еды за прошлую дату доступны командами.
`/cancel` отменяет текущий диалог и все ещё не подтверждённые черновики пользователя.

## AI

По умолчанию выключен. Реализован адаптер OpenAI Responses API с `text.format`
и JSON Schema; модель выбирается через `AI_MODEL`. Нужны доступ к API и отдельный
API-ключ. Бот не предполагает наличие доступной модели или оплаченного API.

```bash
nano .secrets/ai_api_key
chmod 600 .secrets/ai_api_key
export AI_API_KEY_FILE="$PWD/.secrets/ai_api_key"
export AI_PROVIDER=openai
export AI_MODEL=your_available_model
export AI_ENABLED=true
export AI_DAILY_USER_LIMIT=10
export AI_DAILY_GLOBAL_LIMIT=50
```

Первый запрос требует согласия пользователя. Передаётся только описание с уточнениями,
без ID, веса и истории. `/ai off` отзывает согласие и отменяет ожидающие черновики;
уже отправленный запрос отозвать нельзя. `AI_RESPONSES_URL` позволяет указать
доверенный HTTPS endpoint с совместимым Responses-контрактом.

Оценка не является проверенными данными ресторана. Ручной ввод всегда доступен.
Лимиты ограничивают **число заданий за UTC-день**, включая неудачные, а не сумму
в валюте. Денежный предел задайте также у провайдера. Автоматического повторения
платного запроса при неоднозначном сетевом сбое нет: повтор — отдельная кнопка,
тоже расходующая лимит. После аварии running-задание отмечается failed; черновик
можно продолжить через прежние кнопки до истечения часа.

## Надёжность и границы

- Каждая входящая операция и отметка её обработки фиксируются одной транзакцией.
  Повтор `update_id` не создаёт второй записи. Повтор подтверждения тоже безопасен.
- Telegram не даёт ключ идемпотентности для sendMessage: при сбое после принятия
  ответа возможен повтор сообщения. Учёт воды/еды при этом не дублируется.
- Один процесс на токен. На Linux дополнительно блокируется повторное открытие
  рабочей БД другим экземпляром приложения. В Windows этот lock не реализован;
  Windows-сборка предназначена для проверки, рабочая среда — Linux.
- История дат фиксируется в момент ввода; изменение timezone её не передвигает.
- Хранятся описания, подтверждённые items, UTC, локальная дата и исходный timezone.
  Не публикуйте базу. Удаление записи — логическая отмена, не стирание персональных данных.
- Это первая версия: нет каталога ресторанов, OCR/фото еды, веб-панели и автоматического
  развёртывания на сервер. Установка сервера выполняется отдельно по инструкции.

## Проверки

`ctest` проверяет парсинг величин, даты, изоляцию, дедупликацию, подтверждения,
историю норм, AI-ошибки и согласие, напоминания, восстановление backup и inbox.
Linux CI также строит PNG и выполняет вариант с AddressSanitizer/UBSan.
Реальный обмен с вашим ботом и AI требует ваших локальных секретов и отдельного smoke-теста.

Источники контрактов: [Telegram Bot API](https://core.telegram.org/bots/api),
[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses),
[SQLite backup](https://sqlite.org/backup.html).

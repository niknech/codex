| Файл | Что понять |

| `src/bot.cpp` | Состояния диалога, draft, подтверждение |

| `tests/tests.cpp` | Примеры поведения без сети и секретов |

## Один ввод воды целиком

1. `main` вызывает getUpdates. `Bot::ingest` сохраняет исходные события и новый offset
   в одной транзакции. Telegram может прислать то же событие снова; PK inbox не даст дубль.
2. `process_one` берёт событие, проверяет личный чат и allowlist. Затем открывает savepoint.
3. `message` передаёт аргумент в `water_ml`: строка `0,5 л` становится целым `500`.
4. INSERT создаёт строку entries с владельцем, UTC, timezone и локальной датой.
5. `say` кладёт будущий ответ в outbox. Отметка inbox.done фиксируется вместе с INSERT.
6. Отдельный поток `deliver_one` отправляет ответ. Он не держит SQL-транзакцию во время сети.

При неверном вводе откатывается savepoint, но сохраняется объяснение ошибки и
пометка обработки события. При неожиданном сбое вся транзакция откатывается,
событие остаётся для следующего запуска.

## Привычное из C и его эквивалент

| В C | Здесь |
|---|---|
| `char*` и размер | `std::string` владеет буфером |
| указатель на структуру | `T&` — ссылка на существующий объект, без передачи владения |
| `malloc/free`, goto cleanup | Конструктор/деструктор и RAII |
| `sqlite3_finalize` в каждом выходе | `unique_ptr` с deleter вызывает его сам |
| код возврата и цепочка проверок | Исключение до границы обработки операции |
| динамический массив | `std::vector` |
| callback + void* | В CURL остаётся C callback; на C++ стороне `std::function` |
| глобальный контекст | `Bot` получает Database и Config по ссылке |

RAII — ресурс принадлежит объекту. `Transaction` начинает транзакцию в конструкторе.
Её деструктор делает ROLLBACK, если не вызван commit. Это работает и при исключении.
`Database` закрывает sqlite3-соединение при выходе из области видимости.

## Почему еда — сначала черновик

AI может ошибиться. Поэтому draft не участвует в totals. Только пользовательская
кнопка save превращает его в entries. У draft есть владелец, версия, срок и статус.
Результат AI старой версии отбрасывается; старая кнопка save не может сохранить
новую оценку. UNIQUE(entries.draft) — второй уровень защиты от повтора.

БЖУ всех блюд суммируются C++-кодом, не берутся из сгенерированной строки «итого».
Вода хранится в мл, вес в граммах, нутриенты — REAL; округление только при выводе.

## Почему три потока

Главный получает сообщения и применяет быстрые операции. AI может ждать сеть до
25 секунд; отдельный worker не блокирует воду и напоминания. Отправка Telegram
тоже отдельная. У каждого потока своё соединение SQLite и CURL handle.
SQLite сериализует короткие записи, WAL разрешает параллельное чтение.

## Где менять поведение

- Новая кнопка: `menu` и `message`, плюс тест поведения.
- Диапазон допустимой воды: `water_ml`, плюс граничные тесты.
- Текст оценки: `estimate_text`.
- AI-контракт: `ai_request`, `ai_response`, `validate_estimate` вместе.
- Новое поле в базе: следующая миграция и обработка версии в `Database::migrate`.
  Нельзя менять только старый SQL после выпуска существующих баз.
- Напоминание: `reminders`, уникальный rule и тест порога/времени.

Сначала попроси агента показать затрагиваемый путь и ожидаемое поведение. Затем
пусть он реализует и докажет его тестом. Ты можешь проверять архитектуру без
самостоятельного набора реализации.

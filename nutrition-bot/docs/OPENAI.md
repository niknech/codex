# Оценка еды через OpenAI

Еда → Завтрак / Обед / Ужин → С помощью AI → текст с составом и порцией.
После выбора AI описание отправляется в OpenAI сразу; предупреждение показано на экране ввода.
История дневника, вес и Telegram ID в запрос не включаются; `store=false`.
Поиск по цифрам штрихкода доступен в режиме [товаров](PRODUCTS.md). Фото не распознаются.
Оценка еды по описанию приблизительна, это не измерение.
Если порция неясна, AI принимает обычную и показывает допущения вместе с КБЖУ. Кнопка «Уточнить» позволяет изменить порцию по желанию.
КБЖУ попадают в дневник только после «Записать»; их можно исправить вручную.

## Ключ и оплата

1. Открой https://platform.openai.com/ и настрой биллинг API.
2. Создай ключ в https://platform.openai.com/api-keys . Не отправляй ключ в чат или Git.
3. На сервере: `sudo nano /etc/nutrition-bot/ai_api_key`. Вставь ключ одной строкой.
4. Проверь права: `sudo chmod 600 /etc/nutrition-bot/ai_api_key`.
5. После установки версии с AI-меню открой `sudo nano /etc/nutrition-bot/config.env`:

```ini
AI_ENABLED=true
AI_PROVIDER=openai
AI_MODEL=gpt-6-luna
AI_WEB_SEARCH_ENABLED=true
AI_DAILY_USER_LIMIT=10
AI_DAILY_GLOBAL_LIMIT=50
```

Перезапусти: `sudo systemctl restart nutrition-bot`.
Проверь: `sudo journalctl -u nutrition-bot -n 30 --no-pager`.
Не включай AI с пустым ключом: проверка конфигурации остановит запуск службы.
Секрет служба получает через systemd LoadCredential, а не из исходников.

## Расходы и модель

Модель по умолчанию — `gpt-6-luna`, reasoning.effort=low, максимум 2500 выходных токенов.
На 12 октября 2026: $0.10 за 1M входных и $0.50 за 1M выходных токенов.
Поиск оплачивается отдельно: $0.01 за вызов поиска плюс токены найденного текста.
Дневные лимиты считают запросы AI (включая неуспешные), а не доллары и не поиски.
Платные запросы автоматически не повторяются.

## Поиск в интернете

`AI_WEB_SEARCH_ENABLED=true` разрешает встроенный web_search. Модель сама решает,
нужен ли он: инструкция требует искать конкретные бренды, блюда ресторанов и ссылки,
а обычные продукты оценивать без поиска. Предпочтение — официальным сайтам и меню.
На ответ разрешено максимум 2 вызова встроенного инструмента, контекст поиска — low.
Это ограничивает число вызовов, но не фиксирует точную цену ответа.
Если точные сведения не найдены, модель должна выдать приблизительную оценку без вопросов.
Ошибки самого API обрабатываются как раньше: ручной ввод или повтор по кнопке.

Цитаты из ответа API сохраняются в черновике и отображаются как ссылки под КБЖУ
(до 3 уникальных HTTP(S)-ссылок). Если API не прислал цитаты, ссылок не будет.
Наличие ссылки не гарантирует точность размера порции: проверяй карточку перед записью.
При ручной правке КБЖУ источники исходной оценки сохраняются.
Структура SQLite не меняется; старые черновики совместимы.

Чтобы отключить только поиск, в `/etc/nutrition-bot/config.env` установи:

```ini
AI_MODEL=gpt-6-luna
AI_WEB_SEARCH_ENABLED=false
```

Затем `sudo systemctl restart nutrition-bot`. Пересборка для переключения не нужна,
но сначала необходимо установить версию программы с поддержкой этой настройки.
Если параметр отсутствует, поиск выключен; разрешены только `true` и `false`.
Существующее значение `AI_MODEL` сохраняется: замени его явно для перехода на Luna.
Стартовый журнал показывает, включён ли поиск. Ключ остаётся прежним.

## Проверка

В Telegram введи «100 г варёного риса без масла». Дождись карточки КБЖУ,
исправь при необходимости и подтверди. Проверь рубрику в итогах дня.
До подтверждения записи в дневнике быть не должно.

401: проверь ключ. 429: баланс/лимиты API. 403: доступ аккаунта и сервера.
Сетевой тайм-аут: проверь доступ сервера к api.openai.com и api.telegram.org.
Ключи и описания еды не выводятся в диагностический журнал.
Для отключения AI верни `AI_ENABLED=false` и перезапусти службу.

# Сборка и запуск на твоём Windows-ноутбуке

Сейчас бот работает напрямую в Windows. Здесь уже настроены MinGW GCC, CMake,
Ninja, SQLite, libcurl, JSON, date/tz и переносимый gnuplot. WSL для этого запуска
не нужен. Серверная Linux-сборка описана отдельно в SERVER.md.

## Пересобрать после изменения кода

Открой PowerShell в папке `nutrition-bot` (там, где лежит CMakeLists.txt):

```powershell
.\scripts\rebuild-local.ps1
```

Если политика PowerShell блокирует локальный скрипт, разреши его только для
этого запуска, не меняя системные настройки:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\rebuild-local.ps1
```

Скрипт останавливает текущий экземпляр, делает резервную копию SQLite, собирает
программу, запускает тесты и включает бота. При ошибке сборки или тестов он
оставляет бота остановленным и показывает ошибку. Python нужен только для backup.

## Те же действия вручную

```powershell
.\data\local.ps1 stop
$env:PATH = "C:\msys64\mingw64\bin;$env:PATH"
$env:BOT_TZDATA_DIR = "$PWD\build\tzdata"
cmake --build build -j2
# Продолжай только если сборка успешна:
ctest --test-dir build --output-on-failure
# Продолжай только если все тесты прошли:
.\data\local.ps1 start
.\data\local.ps1 status
```

При изменении схемы БД используй скрипт выше — он также делает резервную копию.
Не запускай старый бинарник после новой миграции без проверки совместимости.

`cmake --build` компилирует изменившиеся .cpp в объектные файлы, затем линкер
собирает `.exe`. Это тот же процесс, что в C; CMake хранит зависимости между
модулями, а Ninja решает, что пересобрать. `-j2` разрешает два задания одновременно.

## Что где находится

| Путь относительно nutrition-bot | Назначение |
|---|---|
| `src/`, `include/` | Реализация C++ и объявления |
| `build/nutrition-bot.exe` | Собранный бот |
| `build/bot-tests.exe`, `build/ui-tests.exe` | Автотесты |
| `data/local.sqlite3` | Рабочий дневник |
| `data/local-config.json` | Твой список разрешённых Telegram ID |
| `.secrets/telegram_token` | Локальный токен |
| `data/local.ps1` | Запуск, остановка, проверка процесса |
| `data/local-errors.log` | Диагностика и подтверждения доставки |
| `build/tzdata` | Часовые пояса для Windows |
| `build/local-tools/gnuplot` | Генератор графиков |

`data`, `.secrets` и `build*` исключены из Git. На другом компьютере их нужно
настроить заново. Не запускай .exe двойным щелчком: ему нужны переменные окружения,
которые задаёт `local.ps1`. Одновременно должен работать один экземпляр на токен.

## Как убедиться, что бот работает

```powershell
.\data\local.ps1 status
Get-Content .\data\local-errors.log -Tail 20
```

`Bot started` — процесс начал работу; `Received` — сообщение получено;
`Delivered` — Telegram принял ответ; `Delivery failed` — отправка не удалась.
Окончательная проверка — ответ на `/start` и кнопки в Telegram.

Для просмотра новых строк: `Get-Content .\data\local-errors.log -Tail 20 -Wait`.
Ctrl+C останавливает просмотр журнала, сам бот продолжает работать.
Бот работает, пока ноутбук включён, подключён к сети и не спит.

## Изменения интерфейса и база версии 2

Еда: Завтрак / Обед / Ужин → Вручную → название → калории, белки, жиры,
углеводы. Есть готовые числа, возврат на шаг назад и быстрый ввод четырёх чисел.
AI-кнопка пока объясняет недоступность; платных запросов этот экран не делает.
Старые текстовые команды сохранены для совместимости, но для нового ввода не нужны.

Вес: сначала число, затем Сегодня / Вчера / календарь. Перед заменой веса за
уже занятую дату бот показывает прежнее измерение и просит подтверждение.

Миграция 002 добавляет поле category к drafts и entries. Старые записи получают
`unspecified` («Без рубрики»), их даты и значения не меняются. Итоги включают их
в общие суммы. Бинарник старой версии не понимает номер схемы 2; для полного
отката нужна соответствующая резервная копия или исправленная новая версия.

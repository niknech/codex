# Как участвовать в разработке, не писать код вручную и понимать его

Для текущей установки Windows/MinGW используй [WINDOWS.md](WINDOWS.md).
Ниже сохранён также альтернативный сценарий WSL. Практический порядок обновления
существующего сервера — в [инструкции администратора](ADMIN_GUIDE.md).

Твоя роль — автор поведения и проверяющий. Ты задаёшь сценарий, выбираешь удобный
интерфейс и проверяешь бота. Агент реализует, объясняет изменения и запускает тесты.
Знание C пригодится для чтения: здесь нет необходимости начинать с основ циклов.

## 1. Где хранить проект

GitHub хранит общую историю: `niknech/codex`, подкаталог `nutrition-bot`.
На ноутбуке хранится рабочая копия. На сервер попадает только проверенный релиз.
У ноутбука и сервера отдельные боты, токены и базы.

На этом ноутбуке WSL при подготовке проекта не был установлен. Для обычной
разработки используй Debian в WSL2. Открой PowerShell от администратора:

```powershell
wsl --install -d Debian
```

Если потребуется, перезагрузи Windows. Открой Debian и создай Linux-пользователя.
Это пользователь ноутбука; он не обязан совпадать с серверным.

Дальше **в Debian WSL**:

```bash
sudo apt update
sudo apt install build-essential cmake ninja-build git pkg-config \
  libcurl4-openssl-dev nlohmann-json3-dev libsqlite3-dev sqlite3 \
  libhowardhinnant-date-dev tzdata gnuplot-nox fonts-dejavu-core \
  ca-certificates openssh-client
mkdir -p ~/projects
cd ~/projects
git clone https://github.com/niknech/codex.git
cd codex
```

Пока первоначальный pull request не объединён, переключись на его ветку:

```bash
git switch nutrition-bot-initial
```

После объединения используй `main`. Открой папку `codex` в редакторе с поддержкой
WSL. В VS Code с расширением WSL из терминала Debian можно выполнить `code .`.
Сборка и запуск — внутри Debian, в `nutrition-bot`, по README.
Для записи на GitHub настрой вход через GitHub CLI (`gh auth login`) или SSH-ключ.
Не используй пароль аккаунта как пароль Git и не помещай токен в URL репозитория.

## 2. Обычный цикл одной доработки

Когда первая версия уже объединена:

```bash
cd ~/projects/codex
git switch main
git pull --ff-only
git switch -c feature/water-buttons
```

Теперь дай агенту задачу в чате, который открыт на этой папке:

> В nutrition-bot добавь на экран воды кнопку 350 мл. После нажатия покажи итог
> дня и отмену именно этой записи. Сам реализуй изменение, проверь тесты,
> покажи результат и коротко объясни изменённый путь от кнопки до SQLite.

Хорошая задача отвечает на три вопроса: что нажимаю/ввожу, что вижу, что сохраняется.
Не нужно заранее придумывать классы или называть файлы. Можно приложить пример
диалога. Полезно добавлять: «сначала объясни спорные варианты», если поведение
ещё не определено.

Проверь тестового бота руками. Затем попроси:

> Покажи изменённые функции, объясни их через аналогии с C. Отдельно объясни,
> кто владеет ресурсами и что откатывается при ошибке. Подготовь commit и PR.

Если выполняешь Git сам, из корня `codex`:

```bash
git status
git diff
git add nutrition-bot
git diff --cached
git commit -m "Add 350 ml water button"
git push -u origin feature/water-buttons
```

На GitHub открой **Compare & pull request**. PR — предложение объединить ветку
с `main`: можно посмотреть изменения по строкам, обсуждение и результаты тестов.
Дождись зелёных проверок и проверь поведение тестового бота. Затем нажми Merge.
Агент может подготовить PR по твоей просьбе; ручной ввод кода не обязателен.

`git push` загружает исходники в GitHub. **Он не обновляет домашнего бота**.
Для этого нужен отдельный выпуск по SERVER.md.

## 3. Как учить C++ на этом проекте

Начни с `docs/CODE_TOUR.md`, затем `domain.cpp`. Следующая задача агенту:

> Разбери water_ml и Database::rows. Я хорошо знаю C: пропусти основы,
> объясни std::string, ссылки, исключения, RAII и unique_ptr.
> Дай два вопроса для проверки понимания, код за меня не переписывай.

После каждой доработки разбирай один путь целиком: сообщение → проверка → запись → ответ.
Полезнее понять, почему транзакция откатывается, чем запоминать всю стандартную библиотеку.

## 4. Чего достаточно проверять перед выпуском

```bash
cd nutrition-bot
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build -j2
ctest --test-dir build --output-on-failure
```

В тестовом Telegram: вода → отмена; вес → повторный вес; еда → отмена/подтверждение;
отчёт и график; перезапуск без потери данных. AI тестируй отдельно, когда включён.
Никогда не запускай ноутбук и сервер с одним токеном одновременно.

Файлы `.secrets`, `.env`, `data`, `build` и SQLite исключены из Git. Перед каждым
коммитом всё равно просматривай `git diff --cached`.
